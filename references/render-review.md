# Rendered review and rollout

For a material redesign, capture a representative baseline if it is accessible. Run the normal application and use the authorized environment and data. Review one real task per surface family in the first pass. Use the same viewport, data scope, and permissions for comparisons where possible.

Check the rendered work in this order.

1. Find the primary decision and action quickly. Look for equal-weight regions, labels the user must infer, weak context, and space that could expose an important row or mark. Keep a purposeful visual idea when it improves recognition without slowing repeated work.
2. Inspect contrast over the actual background, font fallback, alignment, tabular values, long labels, focus, scrolling, overlay placement, and touch. Test widths that move the actual layout, including a narrow one and any supported additional appearance mode affected by the change.
3. Exercise normal and representative edge states. Validate real data values against their owning response. Verify the highest-impact actions, such as query, export, save, navigation, or a permission boundary, when authorized. Check the output of export when it is part of the workflow.
4. Fix the most consequential observed issues and recapture affected states. Use screenshots and probes as complementary evidence. Run targeted checks plus the requested build or type checks. Compare known unrelated diagnostics against a baseline when available.

For a rollout, migrate shared tokens and shell before duplicating page CSS. Identify inherited visual rules, their remaining consumers, and the working behaviors they happen to carry. Remove obsolete rules after replacing those responsibilities. Review common components and representative pages, then check the registered surface inventory for gaps. Record what was confirmed by the browser, what was checked through shared code, and any environment or data limits that remain.

Verify the actual cascade on menus, selected states, fixed cells, inputs, and overlays. A previous skin can still win through selector specificity or a separate overlay container. Inspect both the pixels and the computed foreground, background, and boundary. After correcting an inherited rule, revisit a surface that uses the same component in a different state.
